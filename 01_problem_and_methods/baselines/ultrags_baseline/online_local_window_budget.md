# Online Local Window：每帧等预算步数调度（推导与伪代码）

本文把「Offline 总步数 \(T\)、\(N\) 帧 → 平均每帧 \(S=T/N\) 步」搬到 **滑动窗口长度为 \(W\)** 的 Online 设定下，给出一套**人为分配**各窗口内步数、使**每一帧累计优化次数均为 \(S\)**（理想情况）的规则。与当前 `methods/ultrags/online_plugins.py` 里「每帧固定 `iters_per_frame`、只 render 当前帧」的实现**不同**；若要在代码里对齐本文，需单独实现按窗计数或按帧多视图调度。

---

## 1. 符号与目标

| 符号 | 含义 |
|------|------|
| \(N\) | sweep 帧数 |
| \(T\) | 与 Offline 对齐的总优化步预算 |
| \(S = T/N\) | 目标：每一帧累计被计入的优化步数（有理数；实现时可取整并用收尾补齐） |
| \(W\) | Local window 长度（同时参与 local 的连续帧数），\(W \ge 1\) |

**理想目标**：序列结束后，每帧 \(i \in \{0,\dots,N-1\}\) 的计数 \(c_i\) 满足 \(c_i = S\)（或实现上 \(\sum_i c_i = T\) 且各帧尽可能接近 \(S\)）。

**\(W=1\)**：平凡。每帧单独跑 \(S\) 步即可。

---

## 2. 窗口索引

滑动窗口共

\[
M = N - W + 1
\]

个位置：

- 窗口 \(k=0\)：帧 \(\{0,1,\dots,W-1\}\)
- 窗口 \(k=1\)：帧 \(\{1,2,\dots,W\}\)
- …
- 窗口 \(k=M-1\)：帧 \(\{N-W,\dots,N-1\}\)

对每个窗口 \(k\)，向当前窗口内的帧分配一步数增量 \(\Delta^{(k)}\)（可对不同帧不同）。

---

## 3. 三段式分配（与 \(W=2, W=3\) 手算一致）

### 3.1 第一个窗口 \(k=0\)

窗口内从**老到新**的第 \(j\) 个槽位（\(j=0,\dots,W-1\)）对应全局帧 \(j\)，分配：

\[
\Delta^{(0)}_j = \frac{S}{j+1}
\]

即依次为 \(S,\; \dfrac{S}{2},\; \dfrac{S}{3},\; \ldots,\; \dfrac{S}{W}\)。

**例**（\(S=150, W=3\)）：帧 \(0,1,2\) 分别 \(+150,\,+75,\,+50\)。

### 3.2 第二个窗口 \(k=1\)

当前窗口为 \(\{1,2,\dots,W\}\)。**最老帧（全局下标 \(1\)）**再分配 \(\dfrac{S}{2}\)，其余 \(W-1\) 帧各分配 \(\dfrac{S}{W}\)：

\[
\Delta^{(1)}_{\text{帧 }1} = \frac{S}{2},\qquad
\Delta^{(1)}_{\text{帧 }2,\dots,W} = \frac{S}{W}
\]

**例**（\(S=150, W=2\)）：帧 \(1,2\) 各 \(+75\)。
**例**（\(S=150, W=3\)）：帧 \(1,2,3\) 为 \(+75,\,+50,\,+50\)。

### 3.3 第三个窗口起 \(k = 2, 3, \ldots, M-1\)

窗口 \(\{k, k+1, \dots, k+W-1\}\) 内 **每一帧** 各分配 \(\dfrac{S}{W}\)：

\[
\Delta^{(k)}_i = \frac{S}{W}\quad \text{（对窗口内所有 } i \text{）}
\]

**例**（\(S=150, W=3\)）：窗口 \(\{2,3,4\}\) 为 \(+50,\,+50,\,+50\)。

---

## 4. 内部帧计数闭合（直观）

对足够「靠中间」的帧 \(i\)，会依次经历：

- 首次进入窗口时的调和份额（若在 \(k=0\) 已出现）；
- 在 \(k=1\) 中作为非最老或最老的一次 \(\dfrac{S}{2}\) / \(\dfrac{S}{W}\) 组合；
- 随后在多个窗口中反复各得 \(\dfrac{S}{W}\)。

按上表累加，可使内部帧在 sweep 结束时达到 \(c_i = S\)（与 \(W=2,3\) 手算表一致）。

---

## 5. 首尾与总步数

- **首帧**：在 \(k=0\) 即拿 \(\Delta^{(0)}_0 = S\)，之后仍可能随后续窗口再拿 \(\dfrac{S}{W}\) 等，需按完整下标求和核对；若设计目标是「首帧也恰为 \(S\)」，应只用上表到「该帧计数首次达到 \(S\)」为止，或对后续窗口跳过已满帧（实现细节由工程约定）。
- **尾帧**：常出现「最后一个窗口内某帧仍 \(< S\)」——在仍含该帧的窗口内（或单独）再执行 **\(S - c_i\)** 步补齐（例：\(W=2,\,N=200\) 时帧 \(199\) 再补 \(75\)）。

**总步数**：各窗 \(\Delta\) 之和未必恰为 \(T\)；若与 Offline 硬对齐 \(\sum_i c_i = T\)，可在收尾对未满帧做 top-up，或对 \(S\) 做微调。

---

## 6. 伪代码

```
S ← T / N
对每个帧 i：c[i] ← 0

# 窗口 k = 0：帧 0 .. W-1
对 j = 0 .. W-1：
    c[j] += S / (j + 1)

# 窗口 k = 1：帧 1 .. W
c[1] += S / 2
对 j = 2 .. W：
    c[j] += S / W

# 窗口 k = 2 .. N-W：帧 k .. k+W-1
对 k = 2 .. N-W：
    对 i = k .. k+W-1：
        c[i] += S / W

# 收尾：任意 c[i] < S 的帧
对 i = 0 .. N-1：
    若 c[i] < S：
        再对帧 i 执行 (S - c[i]) 步（或等价地加计数并跑优化）
```

实现时注意：\(S/(j+1)\)、\(S/2\)、\(S/W\) 是否取整、是否用浮点累计再在最后取整，由数值策略决定；**收尾补齐**是保证「每帧满 \(S\)」或「总和为 \(T\)」的常用手段。

---

## 7. 与「随机从窗口内抽一帧做一步」的区别

若每步在窗口内**均匀随机**选一帧更新，各帧被抽中的次数是随机变量，**期望上一般不能**保证每帧恰 \(S\) 步且 \(\sum = T\) 与 Offline 严格一致。本文调度是 **确定性预算表**，专门用于「每帧等质量」的理想对照。

---

## 8. 与当前代码的关系

当前 `OptimizePlugin` 对**每个 stream 帧**使用固定 `iters_per_frame`，且 **render 仅用当前 `slice_meta`**，**没有**按上表对「窗口内多帧」分配步数，也**没有**维护 \(c_i\) 与本文调度对齐。若要将本文落地，需要新增例如：

- 每窗阶段的步数预算与按帧 render 的循环；或
- 全局计数器 \(c[i]\) 与「下一步该优化哪一帧 / 哪一窗」的策略。

本文档仅记录**预算推导**，不绑定具体插件实现。
