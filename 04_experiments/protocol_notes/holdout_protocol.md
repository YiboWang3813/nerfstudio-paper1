## Interpretation

1. The current interval holdout is deterministic and evenly spaced, not random. It does not create frequent local patterns like `10101`; for the primary sweep, each test frame is isolated and bracketed by train frames.
2. For GS reconstruction metrics, the protocol mostly measures single-slice interpolation inside a dense one-sweep trajectory. Test images are not far from the nearest train slice in physical distance, so a failed idea is unlikely to be explained only by missing immediate neighboring train coverage.
3. For FiMA pose learning, the same protocol is harsher: every isolated test frame removes the two adjacent supervised train edges crossing that frame, and protocol-safe global-contiguous windows are cut into repeated train runs. With 40 holdouts, W=8 windows can become a limiting factor on shorter sweeps.
4. Because `holdout_interval` reuses `train_container` as `test_container`, any method that overwrites the full container pose list before GS evaluation also changes holdout test-frame poses. Reports must state whether evaluation used GT poses or a predicted/replaced pose list.

## Recommended Next Protocol Checks

1. Keep interval holdout for comparable interpolation PSNR/SSIM, but report it explicitly as dense one-sweep interpolation.
2. Add a block or gap holdout sanity split for innovation screening: hold out contiguous chunks so test frames are not always immediate train-neighbor interpolations.
3. For FiMA, decouple pose-network validation from GS interpolation split: train pose edges on contiguous train blocks and evaluate pose on held-out edges/chunks with explicit mm error.
4. Re-read pose-prior experiment conclusions after checking whether replaced test poses were used in holdout evaluation.
