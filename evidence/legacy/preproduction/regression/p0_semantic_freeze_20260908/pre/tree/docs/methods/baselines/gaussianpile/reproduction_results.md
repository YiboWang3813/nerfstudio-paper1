## 2026-06-08 Hyperparameter Checks

A key lesson from the 2026-06-08 investigation is that paper hyperparameters
are a reproduction anchor, not automatically the final dataset-specific
configuration. We therefore checked lower prune thresholds on `synthetic_liver`.

Short 10k probes:

| Job | `prune_opacity` | 5k result | 10k result | Final Gaussians | Decision |
|---:|---:|---|---|---:|---|
| `61530` | `0.0125` | PSNR `14.1286`, 95% black | PSNR `24.4549`, recovered | `818,109` | too slow / too dense |
| `61531` | `0.0150` | PSNR `14.1291`, 95% black | PSNR `23.7853`, recovered | `722,751` | too slow / lower quality |
| `61532` | `0.0175` | PSNR `24.2693`, normal | PSNR `14.1337`, 95% black | `944,089` | unstable |

These probes are not production runs because `engine.iterations=10000` also
changes the LR schedule. They are still useful for rejecting the idea that
lowering the prune threshold is a clean synthetic-liver fix. Lower thresholds
kept too many low-contribution Gaussians, missed the throughput target, and
showed black-frame instability under the short schedule.

The final decision is to keep `prune_opacity=0.02` for `synthetic_liver`,
not merely because it appears in the paper, but because the 30k validation run
is more stable and reaches the best speed/quality tradeoff among the tested
options.

## Paper Alignment

The implementation is aligned with the main GaussianPile paper content needed
for a baseline:

- One scalar alpha per Gaussian.
- No separate learned intensity channel.
- 3D anisotropic Gaussian parameters: mean, scale, quaternion, alpha.
- Focus-aware slice projection with elevational response.
- Additive accumulation, not RGB alpha compositing.
- No SH color and no view-dependent appearance.
- `sigma_z` defaults to dataset elevational spacing, matching the paper's
  recommended `sigma_z = delta_z` setting when no calibrated PSF is available.
- Adam training for 30k iterations.
- Learning rates: means `0.0006`, alpha `0.02`, scale `0.002`, rotation
  `0.001`.
- Learning-rate final multiplier `0.1`.
- Loss `L1 + 0.2 * SSIM`.
- Density control window `500-25000`.
- Density control threshold `densify_grad=5e-5`.
- Prune threshold `tau=0.02`.
- 1M initial Gaussians.

Explicitly out of scope for this baseline:

- Compression.
- Quantization.
- Differentiable voxelization.

Those are auxiliary innovations and are intentionally excluded from the
production comparison baseline.

## Code Alignment

### Method Runtime

`methods/gaussianpile/gaussian_container.py` owns the canonical Gaussian
parameters. The method exposes one scalar alpha through the `alphas` property,
which aliases the underlying opacity parameter. There is no learnable intensity
parameter in GaussianPile state.

`methods/gaussianpile/render.py` is the method-level render entry. It builds a
`GaussianPlieRenderConfig`, resolves `sigma_z_mm` from dataset metadata when
unset, uses `GaussianPlieRenderer`, and supports chunked additive rendering for
large active Gaussian sets.

### CUDA Renderer

`ops/gaussianplie_renderer` implements the custom renderer. The public API is
`(means, scales, quats, alphas, pose)`. Internally, the wrapper still passes an
all-ones intensity tensor to reuse the lower-level ABI, but that tensor is not
a model parameter and does not change the single-alpha formulation.

The renderer covers the important reproduction math:

1. Transform Gaussian mean and covariance into the slice frame.
2. Inject elevational precision using `1 / sigma_z^2`.
3. Project to a 2D screen-space marginal.
4. Apply off-plane focus attenuation.
5. Apply determinant normalization.
6. Accumulate contributions additively.

### Density Control

The latest code removes the earlier ratio-based prune guard from the production
config by setting:

```yaml
max_prune_fraction_per_step: 0.0
min_keep_ratio: 0.0
```

The pruning decision uses a focus/tile-aware opacity score:

```text
score = alpha * focus_response * sqrt(screen_radius_px)
prune when score < prune_opacity
```

This is the main practical adaptation for `synthetic_liver`. Raw
`alpha < 0.02` over-pruned relevant slice contributors and produced all-black
failures. The focus/tile-aware score keeps the pruning rule tied to the paper's
slice contribution model while avoiding artificial count guards.

## Historical Debugging Notes

The early acceptance run around 2026-05-27 was fast but low quality, with PSNR
around `17`. The main causes were:

- overly narrow render support;
- aggressive culling;
- a speed-oriented renderer path that clipped weak additive contributions;
- density control pruning under a support model that did not match the final
  focus renderer.

The later 2026-05-30 report showed best-checkpoint quality around
`25.6-25.8`, but that version still contained historical assumptions that were
revisited during the anomaly investigation. The 2026-06-08 conclusion is more
conservative and better scoped: for the current committed code, use the
canonical six-sweep rerun and the saved best checkpoint protocol.

The anomaly report in
`docs/methods/baselines/gaussianpile/diagnostics_report.md` identified two
practical production failures in the old comparison rows:

- final 30k GaussianPile artifacts could be black even when the best checkpoint
  metric looked reasonable;
- `vis/` represented the final collapsed state rather than the best selected
  state, so visual inspection disagreed with the table.

The stable rerun fixes this operationally by restoring the saved best
Gaussian container before final artifact generation when needed. Historical bad
GaussianPile folders in `outputs/production/comparisons/synthetic_liver_6method_best` were
deleted after validation, and the accepted rerun folders were renamed to the
canonical no-suffix names used by the comparison scripts.

Use this protocol for production comparisons:

```text

Dataset: synthetic_liver
Config: configs_hydra/experiment/preproduction/baseline_reproduction/gaussianpile/main_30k.yaml
Model config: configs_hydra/model/gaussianpile.yaml

Evaluation: holdout_interval, every 5,000 iterations
Reported metric: saved best checkpoint by held-out PSNR
Canonical comparison rows: no retry suffix, e.g.
  synthetic_liver_r1_gaussianpile_1m_30k_dc_nmax2m_best
Recommended output root: outputs/production/comparisons/synthetic_liver_6method_best
```

For a future GaussianPile-only six-sweep rerun, use the existing comparison
array mapping. GaussianPile is method index `4` in
`scripts/production/comparisons/us_synthetic_recon_benchmark_v1/run_task_6method.sh`, so the six

```bash

  scripts/production/comparisons/us_synthetic_recon_benchmark_v1/run_task_6method.sh
```

For a full six-method comparison, use:

```bash

```

Do not set `RETRY_SUFFIX` for production GaussianPile rows. Diagnostic reruns
may use a suffix, but they should either stay outside the production summary or
be cleaned up before handing results to a comparison-focused agent. The final
checkpoint is kept as a late-training diagnostic; the best validation
checkpoint is the stable baseline metric, and the final restored artifacts are
used to keep visual folders non-black.
