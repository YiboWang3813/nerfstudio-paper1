Audience: experiment-running agents. This file records the current production

## Production Status

Use the pose-QC cropped export for production. The native p100k export is kept
for traceability and diagnostics, but it contains in-plane sliding segments that
can produce visible slice misalignment with the current reconstruction geometry.

Recommended production default for Ours:

- Scene config: `scene=tus_rec_2024_qc`
- Main experiment config: `experiment=preproduction/dataset_preflight/tus_rec_2024/tus_rec_2024_qc_confirm_30k`
- Working image shape: `288 x 384` (`110592` pixels/frame)
- Online image downsample: `1`
- Online axial downsample: `1`
- Initialization: `1M` Gaussians
- Iterations: `30k`
- Elevational corridor: `model.slice_render.elev_corridor_half_mm=0.202`

Do not use `tus_rec_2024_centered`; all active methods support the native
`center_lateral=False` convention. The QC export keeps the same coordinate
system and DatasetMeta, and only crops the frame/time axis.

## Export Scripts

Raw HDF5 to standard sweep export:

`scripts/datasets/tus_rec_2024/prepare.py`

p100k standardization:

`scripts/datasets/shared/build_p100k_datasets.py`

Pose-QC cropping for production:

`scripts/datasets/tus_rec_2024/qc_crop.py`

Default QC rule:

- adjacent motion is converted to local probe coordinates by
  `R_i.T @ (t_{i+1} - t_i)`
- keep a step when:
  - `abs(elevational) >= 0.10 mm`
  - `abs(elevational) >= 1.0 * abs(lateral)`
  - `abs(elevational) >= 0.5 * abs(axial)`
  - step norm is at most `1.5 mm`
- bridge gaps of at most `5` bad steps
- trim `5` frames from each segment boundary
- export only segments with at least `80` frames

This is a data QC rule, not result-based cherry-picking. It removes segments
whose tracked probe motion violates the 3D freehand reconstruction assumption.

Pose formula used by the raw export:

`poses = tforms @ spatial_calibration_from_image_mm_to_tool`

Do not multiply `scaling_from_pixel_to_mm` into poses. Pixel-to-mm spacing is
supplied by `DatasetMeta`; multiplying scale into poses would apply scale twice.

## DatasetMeta

Defined in:

`scene/meta/dataset_meta/tus_rec_2024.py`

Key values:

| field | value |
| --- | --- |
| `name` | `tus_rec_2024` |
| `probe_type` | `linear` |
| `H, W` | `288, 384` |
| `near_mm` | `0.0` |
| `far_mm` | `480 * 0.220979690551758` |
| `width_mm` | `640 * 0.229389190673828` |
| `delta_lateral_mm` | `(640 * 0.229389190673828) / 384` |
| `delta_axial_mm` | `(480 * 0.220979690551758) / 288` |
| `delta_elevational_mm` | `0.404` |
| `center_lateral` | `False` |
| `pose_init_type` | `probe->world` |

The physical calibration comes from the official calibration matrix:

- `scaling_from_pixel_to_mm[0,0] = 0.229389190673828`
- `scaling_from_pixel_to_mm[1,1] = 0.220979690551758`
- `spatial_calibration_from_image_coordinate_system_to_tracking_tool_coordinate_system`
  maps image millimetres to the tracked tool frame.

Although acquisition used a curvilinear probe, the released calibration maps a
rectangular image-coordinate plane to tracker space. The project therefore uses
`probe_type=linear` with left-origin lateral coordinates to match the official
image-coordinate calibration.

## Coordinate Convention

This dataset is different from `synthetic_liver` and `spine_phantom`:

- `center_lateral=False`
- local x starts at the left image column: `x = col * delta_lateral_mm`
- local y starts at `near_mm`: `y = row * delta_axial_mm + near_mm`
- local z is elevational

All active methods have been updated to support this native convention:

- `ours`
- `ultragauss`
- `ultragray`
- `ultrags`
- `ultrags_baseline`
- `slice_adapted_3dgs`
- `gaussianpile`
- `ultranerf`
- `nerfus`

`s2s` is intentionally not maintained for this dataset.
